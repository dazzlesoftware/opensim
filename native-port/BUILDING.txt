OpenSimulator native C++ migration

STATUS

This now includes a runnable C++20 HTTP login/authentication server, shared
framework library, and migration tests. The executable is opensim-native.
It supports XML-RPC and LLSD XML login intake, account lookup, salted passwords,
one-time web keys, persistent authentication tokens, login-level administration,
and grid discovery. SQLite tables use the original schema shapes.

It is not yet a replacement simulator or Robust deployment. Native scene,
capability and complete LLUDP runtime integration remain pending. By default,
valid credentials still fail when required services/admission are unavailable.
Opt-in remote simulation admission now produces XML-RPC and LLSD success
responses after a compatible remote simulator accepts the circuit; see REMOTE
LOGIN COMPLETION below. This does not prove a working viewer session.

All existing behavior remains in scope. source-baseline.json inventories tracked
C# files and project declarations; port-map.json records the scopes implemented
so far. A passing test or an implemented source file does not establish whole
application feature parity. Ignored addon-modules and external dependencies are
not included in the tracked-file baseline and need separate inventories.

BUILD (Windows, Linux, macOS)

Requires CMake >= 3.20, a C++20 compiler with standard threading support,
and the libjpeg, libpng, and FreeType development libraries. The vcpkg manifest supplies
these libraries. Map export labels use Arial when available and Liberation Sans on Linux.

    cmake -S native-port -B native-port/build -DCMAKE_BUILD_TYPE=Release
    cmake --build native-port/build --config Release --parallel
    ctest --test-dir native-port/build -C Release --output-on-failure

On Windows use a Visual Studio developer shell, or a CMake Visual Studio
generator. No .NET runtime or SDK is used by opensim-native or the native tests.

RUN THE SERVER

Copy native-port/native-server.ini.example to a new native-server.ini in your
chosen data directory. Native database paths resolve relative to that file.
From the repository root, for a Visual Studio Release build:

    native-port/build/Release/opensim-native.exe --config PATH/native-server.ini --init-db
    native-port/build/Release/opensim-native.exe --config PATH/native-server.ini --create-user FIRST LAST
    native-port/build/Release/opensim-native.exe --config PATH/native-server.ini --console

On Linux/macOS, replace the executable with native-port/build/opensim-native.
The create-user command reads a password from stdin; it never accepts a password
in process arguments or prints it. --user-level sets the initial account level.
Database initialization refuses existing nonempty files. Executable account startup and enabled local friends, avatar and grid-user
providers run their original migrations before serving requests. Authentication
storage still uses the native current-schema adapter; its original migrations
and provider lifecycle remain pending. Use copies of
existing compatible account/auth databases while parity work is incomplete.

Separate original-style [UserAccountService] and [AuthenticationService]
ConnectionString = "URI=file:NAME.db;Version=3" settings are also supported.
The bundled provider treats a comma as a filename character: the older spelling
URI=file:NAME.db,version=3 selects a file literally named NAME.db,version=3.
Quote the complete INI value to retain semicolons through the scoped INI reader.
Native executable startup now uses the original local ConfigurationLoader pipeline:
ordered and wildcard Include-* files, constant-main-directory include resolution,
master files, override directories, requested environment keys and exact expansion
stages. --inimaster FILE selects a master (native profile default: none).
--inidirectory DIR selects overrides (original default: config); use an absolute
directory when the process working directory differs from the main config directory,
as the original loader tests the combined path but enumerates the raw directory.
--port and --host merge before typed startup validation. File-backed Nini booleans
use true/false; command-line aliases are not copied into file-source owners.
Remote XML configuration and complete simulator hosting remain incomplete. The
single-file IniConfig::load library API remains separate from load_startup.

The default bind address is IPv4 loopback, port 9000. --host accepts IPv4/IPv6
addresses. --port 0 chooses an unused port and prints the actual listening URI.
An occupied port fails instead of sharing traffic with another process.
--console accepts quit or shutdown on stdin. SIGINT/SIGTERM stop the listener.

Endpoints:
    POST / or /login: XML-RPC login_to_simulator and set_login_level
    POST / or /login with application/llsd+xml: LLSD login
    GET /get_grid_info: XML discovery
    GET /json_grid_info: JSON discovery
    XML-RPC get_grid_info: same discovery fields
    GET /health: process/authentication liveness and explicit simulator state
    GET /ready: 503 until simulator sessions can be supported

AllowRemoteSetLoginLevel=false by default. If explicitly enabled, the existing
level >= 200 check and raw MD5-prehash credential convention are preserved.
Login MinLoginLevel, RequireInventory, basic AllowedClients/DeniedClients patterns,
and DeniedMacs/DeniedID0s gates are ported. C++ ECMAScript regex is not a complete
replacement for .NET regex syntax or Unicode matching; that parity gap remains.

TLS AND COMPRESSION

HTTP/XML parsing and SQLite sources are vendored with versions, commit IDs,
source URLs and checksums in third_party/dependencies.json. Builds do not fetch
them. Original dependency licenses are retained. Optional OpenSSL is discovered
through CMake. Unix builds require system zlib for the outgoing gzip profile used
by the original runtime. Windows x86/x64 embeds the isolated native Intel zlib
profile; optional system zlib enables general HTTP Content-Encoding support.
--features reports the server HTTP/TLS features that were built.
OpenSSL must be version 3.0 or newer. The optional vcpkg.json manifest pins a
registry baseline for OpenSSL and zlib. To build with those dependencies through
an installed vcpkg instance, use a fresh build directory:

    cmake -S native-port -B native-port/build-https -DCMAKE_TOOLCHAIN_FILE=VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake -DOPENSIM_REQUIRE_TLS=ON
    cmake --build native-port/build-https --config Release --parallel
    ctest --test-dir native-port/build-https -C Release --output-on-failure

Replace VCPKG_ROOT with the actual vcpkg directory. Selecting that toolchain
explicitly opts into its manifest dependency download/build workflow.

Add -DVCPKG_MANIFEST_FEATURES=offline-im-sql to that configure command to
install the PostgreSQL and MariaDB clients for offline messaging. CMake can
also find these clients in system development packages. Select
OpenSim.Data.PGSQL.dll or OpenSim.Data.MySQL.dll in [Messaging] StorageProvider
and supply the database's ConnectionString in the same section. For a MariaDB
server intentionally configured for plaintext, use the legacy SSL Mode=Disable
connection-string option.

To require HTTPS support at configure time:
    cmake -S native-port -B native-port/build -DOPENSIM_REQUIRE_TLS=ON

Set NativeServer.TlsCertificate and TlsPrivateKey to PEM files to use HTTPS.
For simultaneous region HTTP and script HTTPS, set Network.https_listener
and Network.https_port and provide the same PEM settings. The main region
listener serves HTTP, and the additional listener serves secure script URLs.
The additional listener also accepts a PKCS#12 file through Network.cert_path
and its password through Network.cert_pass. A relative path is resolved from
the configuration directory.
Set Network.https_external to true when a reverse proxy terminates HTTPS.
The additional listener then accepts plain HTTP on Network.https_port without
PEM settings, while scripts still receive HTTPS URLs for the proxy.
For a primary region HTTPS listener, set Network.http_listener_ssl,
Network.http_listener_sslport and Network.http_listener_cn, and configure the
PKCS#12 file with Network.http_listener_cert_path and http_listener_cert_pass.
The plain script listener remains on Network.http_listener_port. Configure
Network.https_listener separately for secure script URLs.
Requesting TLS without OpenSSL fails explicitly, with no plaintext fallback.
The test certificate and private key in tests/fixtures are PUBLIC TEST MATERIAL,
used only by the HTTPS smoke test. Configure your own certificates for a server.
Gzip Content-Encoding is supported when zlib is found. The legacy
X-Content-Encoding alias and all other BaseHttpServer routes remain to be ported.
No proxy headers are trusted; the peer IP is the socket address until the
original trusted-proxy/XFF configuration and validation are ported.

COMPARE TO EXISTING IMPLEMENTATIONS

The optional differential test requires Python >= 3.9, .NET SDK >= 8, and the
.NET 8 runtime/reference pack. It targets net8.0 to match prebuild.xml. It
compiles the original C# files directly, runs the same deterministic input stream
through both implementations, and compares observed outputs. It does not require
NuGet packages or a complete C# OpenSim build.

    cmake -S native-port -B native-port/build -DOPENSIM_DIFFERENTIAL_TESTS=ON
    cmake --build native-port/build --config Release --parallel
    ctest --test-dir native-port/build -C Release --output-on-failure

Reports include build/reference/parity-results.json and
build/login-reference/login-parity-results.json. The login comparison compiles
the original LLLoginHandlers, original interface, and original failed-response
class, using the repository's tracked XMLRPC/OpenMetaverse dependency assemblies.
It checks captured service arguments and failures, not full simulator login.
Reports record source SHA-256
hashes, target framework, scenario counts, differences and float tolerances. Integer results,
permission masks, CRC values and strings must match exactly. Selected floating
point state values use the tolerance recorded in the report.

The reference harness replaces logging/configuration/clock/scheduler dependencies
with test adapters. PermissionMask and tick arithmetic declarations are extracted
from Util.cs. The DOS protector's original Elapsed callback is exercised with a
manually driven scheduler. The native unit tests also exercise a real cleanup
thread. These checks do not validate the original operating system timer or the
full Nini configuration parser. server_network.py also starts real processes,
uses TCP/IPv6/optional HTTPS, checks account/token persistence and concurrent
one-time web-key use, and stops the process through its console. Its report is
build/network-tests/network-results.json. TLS/gzip skips are recorded explicitly.

Optional sanitizer build:

    cmake -S native-port -B native-port/build-asan -DCMAKE_BUILD_TYPE=Debug -DOPENSIM_SANITIZERS=ON
    cmake --build native-port/build-asan --config Debug --parallel
    ctest --test-dir native-port/build-asan -C Debug --output-on-failure

Windows ASan builds require the compiler's ASan runtime to be installed and on
PATH when testing. Non-MSVC builds enable both address and undefined-behavior
sanitizers. CI defines a three-platform comparison matrix and Linux sanitizer
checks. A workflow definition is not evidence that those hosted jobs have run.

COMPATIBILITY DECISIONS

The C++ APIs use namespaces, spans, exceptions and smart pointers. Existing
algorithm behavior is preserved even where surprising: prime helper sqrt bounds,
CRC HashCore offset handling, circular-buffer overflow/Skip/resize/CopyTo behavior,
token debt, the initial +1000-second timestamp, the adaptive constructor flag,
and the DOS concurrency/expiry rules. Do not fix these silently while porting.

Native token buckets reject parent cycles, track parent lifetimes, and unregister
on destruction to avoid dangling pointers. These are explicit native lifetime
adaptations. A destroyed C++ object is not retained as a managed child reference.
Token bucket operations still require the caller's synchronization, as the source
does; only child request registration is locked internally.

PermissionsUtil produces its diagnostic message for the host to log. ThrottleRates
reads the ClientStack.LindenUDP section through an integer-reader callback; the
Nini-compatible configuration loader itself remains unported. BasicDOSProtector
accepts an optional logging sink and shared options; quiesce it before mutating
shared options. Its process/cleanup state is serialized with a mutex, and its
cleanup worker is joined at destruction. Hosts can supply their own scheduler.

Password impersonation, generic auth-info administration, authentication and remaining provider migrations,
MySQL/PostgreSQL and remote account/auth providers remain unported. The native
account store currently covers the normal SQLite password/web-key/token paths.
Grid statistics, the complete HTTP handler registry, JSON-RPC, WebSockets and
the remaining LLUDP scene handlers still need implementation. remaining-work.json
records the next scopes.

The LLUDP codec covers all 387 packet types in the tracked OpenMetaverse assembly.
The protocol directory records the upstream template revision, license, assembly
hash and reflection catalog. tools/generate_lludp_schema.py validates the template
against that catalog and generates src/lludp_schema.inc. Normal builds require no
.NET runtime. Differential tests compare 1548 serialized, zero-coded and decoded
packet cases plus 1548 packet-splitting cases against the original assembly.
Two original fixed-block decoder
failures (TestMessage and ViewerStats) are preserved by default; explicitly pass
baseline_quirks=false to decode_datagram for diagnostic inspection of their bytes.

UdpSocket supports exclusive IPv4/IPv6 binding, bounded datagrams and joined
shutdown. CircuitTransport provides credential and scene-gated admission, packet
ID validation, duplicate suppression, ACKs, retransmission, ping and timeouts.
An admission callback must confirm actual scene creation; matching credentials
alone never create a client. These components are tested over real sockets but
are not yet connected to a complete simulator scene. An optional host executor
runs admission asynchronously; pending packets are queued for replay, repeat
circuit requests get receipt ACKs, and pending queues expire after 60 seconds.
Outgoing packets now use category bandwidth queues, including resend priority,
the source ACK stall gate, viewer throttle settings and adaptive flow feedback.
Automatic splitting matches ToBytesMultiple, including the four hand-written
message overrides that return unsplit bytes. The original one-byte block count
wrap is preserved. If a repeated fixed prefix fills the entire MTU, the original
splitter loops forever; the native splitter throws an explicit length error.
Queue-empty producers now run through a host executor, with the original 20 ms
minimum interval and single-running-producer gate. Disconnect and callback errors
release the gate. Configure scene_throttle_max_bps to share a region token-bucket
parent across clients (zero retains the unconfigured source default). Complete
scene and viewer service handlers remain.

InventoryFolderStore, InventoryFolderService and InventoryService provide the
SQLite-backed inventory path: folder and twenty-field item CRUD/moves, parent
versions, root/type lookup, default creation/repair and skeleton retrieval.
InventoryService provides contents/multiple fetches, system-folder protection,
item invariant restoration, deletion policies, recursive trash purging, active
gestures and asset permission aggregation. Service results preserve ushort version
and short type conversion. Names truncate at 64 UTF-16 units as in the source.
The source excludes type zero from system-folder repair detection, so a repeated
CreateUserInventory creates another Textures folder; this behavior is preserved.
Initialization creates both original inventory tables and indexes, checked against
the original migration schema, and requires an empty destination. The 68 service
differential scenarios compile the original XInventoryService and creator property
with an in-memory reference provider fixture; these comparisons establish service
behavior, not equivalence of every original SQLite provider failure path.
Original migration/import execution, other providers, complete item
serialization and login wiring remain unported. This component is not yet exposed
by the server CLI. Inventory ancestry/purge cycles throw in native code instead
of preserving the original infinite traversal or recursion.

LibraryService loads the existing Nini XML catalog without a managed runtime.
It preserves the process-wide first-initialization behavior, source order,
permission defaults (including the basePermissions/group-permissions quirk),
duplicate handling, shared folder/item references and multiple-item fetch rules.
InventoryFolderTree implements the original recursive/path lookup and mutation
operations. Reference comparisons compile the original LibraryService and
InventoryFolderImpl against the checkout's actual Nini assembly; the shipped
19 folders and 123 items match, with custom malformed/duplicate/order fixtures.
Native tree insertion rejects pointer cycles rather than retaining leaking cycles.
Hosts must serialize mutations to exposed folder/item data.

inventory_login_fields constructs inventory root/skeleton, library root/owner/
skeleton and gesture fields. Four reference scenarios compare the original
LLLoginResponse inventory methods. This helper does not issue login success or
replace the required inventory endpoint, presence, region and capability services.
AgentCircuitManager preserves source lookup and shared-reference behavior;
AgentCircuitData now packs/unpacks its appearance and circuit wire fields as
described below; real scene admission and executable login binding remain pending.

No .NET plugin or C# script compatibility layer exists yet. Preserving those
features without a .NET runtime is an unresolved migration workstream, not an
excluded feature. Native plugin APIs cannot load existing managed assemblies.

PresenceService and NullPresenceStore implement the standalone presence path.
The Null provider is process-wide, retains shared record references and preserves
dictionary slot reuse and its always-false VerifyAgent behavior. The service
implements duplicate policy, login/report/logout/query and region logout. Default
caches are shared across service instances, with five-minute entries and separate
minute purge schedules. Reads do not directly expire entries; the strict timer
comparison, cached stale records and signed timestamp overflow are preserved.
An injected clock uses explicit purge calls for deterministic reference tests.
The native background worker is stopped and joined, and service/provider/cache
operations are serialized to protect native container lifetimes. Callers must
serialize changes to exposed shared records. Sixteen differential scenarios
compile the original service, Null provider and ExpiringCacheOS. Failure tests
cover the source's ignored Store return and ReportAgent exception handling.
The executable can now enable POST /presence with NativeServer.EnablePresenceEndpoint.
It uses the standalone Null provider and the original logout, region logout,
report, getagent and getagents operations; remote login remains refused, as in
the source handler. Requests use the original METHOD/form/list syntax and
ServerResponse XML format. Network/PresenceService service-auth configuration
supports default X-SecondLife-Shard exclusion and inbound BasicHttpAuthentication,
with section overrides, original challenge and credential parsing behavior.
The 152 endpoint comparisons compile the original handler, BaseStreamHandler,
authentication classes and extracted ServerUtils/XML methods; 27 additional
form cases cover duplicate/list/Unicode/replacement rules. Process/network tests
exercise the executable route, authentication and disabled routing.
MySQL/PostgreSQL persistence, full configuration/plugin loading, remote connectors,
outbound auth, arbitrary service XML key encoding, complete model serialization
and login rollback/admission wiring remain. Service exposure does not make viewer
login successful or simulator readiness true.

GridUserService and SqliteGridUserStore implement persistent home/last-region
locations and login/logout state, including 36-UTF-16-unit Hypergrid prefix lookup,
most-recent-record selection and shared positive/negative caches. The original
short-ID negative-cache behavior and cache mutations on failed writes remain.
Vector text preserves the source parser and .NET shortest-significant-digit
formatting, checked against 537 cases from the original types assembly.
Sixteen service scenarios compile the original GridUserService with a fixture
provider; native SQLite persistence and reopen behavior have separate tests.
The executable now uses the original SQLite legacy 001_GridUserStore.sql resource
for grid-user startup and explicit --init-db initialization, with original version
metadata and independent shared provider state. Its schema preserves SQLite's
nullable UserID primary key. The earlier SqliteGridUserStore raw-path helper keeps
the PostgreSQL-shaped compatibility schema for existing explicit probes.
Exact Get queries bind UserID, and source-style GetAll retains the original raw
LIKE prefix formatting. The GridUserData record now has nullable UserID and a
shared ordered dictionary of nullable string values. Unix timestamp fields still
replace managed DateTime objects in the GridUserInfo projection. The optional
POST /griduser endpoint emits original field order, vector strings and invariant
UTC DateTime text. All six original handler methods are implemented, including
default positions, invalid-vector resets, null batch filtering, empty roots and
original service-auth rules;328 source comparisons cover the handler/state paths.
Enable NativeServer.EnableGridUserEndpoint and configure GridUserDatabase to a
separate SQLite file before --init-db. Normal enabled startup runs original
provider migrations and can create its missing grid-user database/table.
GridUserService.ConnectionString overrides GridUserDatabase; Realm defaults to
GridUser. The native CLI still requires a separate empty grid-user file for
--init-db.109 whole original provider/generic/framework/Migration/DTO scenarios
and192 connected-login checks cover startup, queries, references and metadata
across restart. Alternate providers, remote connectors, complete model/runtime
parsing, console/config/module registration and full scene integration remain.

GridRegion, RegionStore/NullRegionStore and the local GridService registry core
are native C++ components. Registration preserves source overlap/reservation/
authentication/move rules and configured flags. Queries cover IDs, handles,
positions, ranges, neighbours and default/HG-default/fallback/online/hyperlink
lists. Deregistration preserves persistent offline records and provider failure
handling. The wire model preserves nullable fields, URI normalization, unsigned
coordinates/handles, copy-constructor omissions and the original absent-sizeY
constructor bug. Null storage retains process sharing, !static isolation,
shared records, scope-ignoring queries, dictionary slot reuse, the source Y-range
sizeX bug, and the private flag helper's singleton delegation/failure.
The reference suite compiles original GridRegion, RegionData, RegionFlags and
NullRegionData, with 24 extracted GridService methods. Its constructor is a
fixture for provider/config/auth injection, not a claim of module-loader parity.
32 scenarios produce 1824 observations; 92 additional model cases check original
field parsing, null/default/error paths and output. Native tests inject database
failures and check invariants. The executable optionally exposes a grid-registry endpoint with Null or SQLite storage, but does
not use the registry to admit viewers yet. Full URI/Unicode host semantics, DNS caching and hostname classification, outbound
Hypergrid behavior, Unicode name collation, large tied-distance sorting,
original providers/migrations, alias URLs, console/plugin registration
and concurrent/runtime integration remain. No successful simulator readiness is
inferred from these component tests.

RegionUri ports the original RegionURI parser and mutable state: accepted schemes
and alternate separators, percent escapes, username/region text, unchecked
coordinates, retained fields on reparsing, local-grid mutation and formatted
address forms. 1618 differential cases compile actual RegionURI with the bundled
OpenMetaverseTypes UTF8 helpers. This preserves dependency slicing/truncation
and zero-filled NUL conversion behavior. Input forms that make the dependency
slice loop indefinitely are rejected in native code; full parity on those
undefined/problematic dependency paths is not claimed. Native tests exercise numeric IPv4/IPv6 resolution and exclusion of unspecified
numeric addresses; the native resolver prefers IPv4 with an IPv6 fallback. The source DNS cache/expiry is not ported yet;
full .NET hostname/URI classification and Unicode/culture behavior remain.
GridService name/URI searches now implement original local/remote selection,
exact-match insertion/limit quirks, local URI mutation and injected Hypergrid
linker delegation. The reference fixture provides deterministic host identity,
DNS and link callbacks; actual remote linking and full URI/Unicode/DNS behavior are still required.
Full original grid handler registration/stream routing and successful viewer
login remain unfinished.

The executable now optionally exposes POST /grid when NativeServer.EnableGridEndpoint
is true. The default NullRegionStore is volatile. An optional SQLite registry
persists records across process restart as described below. All sixteen original GridServerPostHandler method dispatches
are ported, including protocol version 1 negotiation, typed/default arguments,
Result/Message casing, indented failures and null/single/list query results.

lookups, defaults, flags, count-zero behavior, concurrent reads, deregistration,

each native service instance to avoid concurrent mutation/read of provider records.
The endpoint accepts an extra-feature provider callback. The executable supplies
ordinary configured service URLs, grid name/nick/status, export and suppression;
21 profiles compare these with the extracted original SetExtraServiceURLs and
actual OSHHTPHost parser.
GatekeeperURIAlias is now normalized by the native HTTP host model, preserving
scheme/default/explicit ports, rejected entries and the original comma behavior.
The live HTTP suite also exercises aliases. Full Unicode/culture host behavior,
original process-wide root/module/console semantics, full URI/Unicode host

DURABLE NATIVE GRID REGISTRY

Set NativeServer.EnableGridEndpoint=true, GridRegionProvider=SQLite and
GridRegionDatabase=regions.db before --init-db to create a dedicated empty SQLite
region database. GridService.ConnectionString overrides that path and Realm
selects its table (default regions). Normal startup opens the existing table;
it does not initialize or migrate one implicitly. Provider Null retains the
source standalone volatile behavior. Unknown provider names are rejected.
Initialization preflights existing region files and requires a region file
separate from the account/authentication/grid-user files, preventing it from
initializing over those databases. Existing records are never recreated by
normal startup. Multi-file initialization is not one database transaction.
This SQLite adapter is an additional native storage option, not an implementation
of the original PostgreSQL/MySQL drivers or migration engine. It uses the complete
canonical GridStore column-name set. Text UUID/handle representations and SQLite
affinities differ from PostgreSQL types. Queries retain scoped versus unscoped
lookup, escaped LIKE arguments, the maximum-region-size search window, independent
X/Y bounds and flags. Updates preserve existing region names and unprovided
columns, as in the PostgreSQL provider's update path. Driver-specific failure,
collation/type/length behavior and original migrations remain separate work.
Native tests cover storage constraints, scopes, non-square regions, escaping,
column updates, initialization refusal, reopen and persistent offline records.
Process tests register scoped regions over /grid, restart the server, and verify
UUID/size/scope filtering and independent Null storage. The column-name comparison
reads the original GridStore definitions; it does not execute or validate the
original migrations. This storage does not admit viewers or simulate a region.

Default GridService instances use configured native identity when classifying

configuration is tolerated for local grid services, preserving the original
GridInfo(config, null) behavior. Full Hypergrid routing, process-wide module/root
state, DNS cache semantics, complete URI/Unicode behavior and original managed

LOGIN DESTINATION SELECTION

LoginDestinationSelector ports FindDestination and FindAlternativeRegion from
LLLoginService. It preserves home positions, horizontal last-position clamps,
where/teleport flags, default/fallback/online selection and the original search
origin/count. Custom uri: starts retain requested positions during fallback;
direct @-style HG starts remain disabled like the original. Malformed starts
throw, matching the original empty Regex.Match/Single.Parse failure path.
The fixed grammar is parsed without recursive native regex matching, including
very large valid coordinates. Overflow/underflow, NaNs, infinities, signed zero,
invalid clamp bounds and final-LF behavior are covered by comparisons. Thirty-two
scenarios yield 800 observations against actual original destination methods,
grid-method fixtures, models and SDK teleport flags, comparing float bit patterns.
A native integration test uses SQLite region/grid-user services and verifies
selection does not mark the user online before simulator admission.
Set NativeServer.EnableLoginOrchestration=true to connect post-authentication
grid-user lookup, duplicate checks, inventory skeleton retrieval, presence login,
home-info synthesis and destination selection. Configure InventoryDatabase and
GridUserDatabase as separate files before --init-db; SQLite region storage also
needs GridRegionDatabase. Services are created internally even when their HTTP
endpoints are disabled. --create-user creates inventory folders in this mode;
the HTTP account service now uses provisioning and optional default inventory
items as described below. Saved-model retrieval and avatar persistence are
available when enabled; full CLI provisioning remains pending. Existing databases are not migrated automatically.

Failure ordering and presence rollback follow the original service, including
optional/null/empty inventory behavior and exceptions during cleanup. A source
fixture compiles the actual post-authentication control-flow block with actual
destination/grid methods and instrumented service failures; it compares 512
preparation outcomes and dependency traces. Native integration and HTTP tests
exercise durable inventory and verify failed admission never marks users online.
The duplicate recovery hook supports the source's first/second logout ordering.
The executable sends the original grid_instant_message god-kick fields and
Messaging.MessageKey to the stale session's region over XML-RPC, with a 10-second
HTTP timeout and normal certificate verification when HTTPS is compiled. Like
the source, it clears stale grid-user state even if delivery fails. Fifty-five HTTP
and persistence checks cover rejected IM delivery, faults, malformed responses,
success and connection refusal. This focused helper does not implement the
general IM routing service.
Remote connectors, HG suitcase, friends/gestures, launch
retry, scene/capability admission and successful LLLoginResponse remain pending.
After destination selection and Godlike flag calculation, login now fetches the
optional avatar service appearance and retains its nullable reference in
PreparedLogin. The executable uses SQLite avatar conversion when enabled.
Conversion errors follow the original internal-error response and presence
cleanup; authenticated /avatar item updates/reset reproduce and repair that
failure over real HTTP. The preparation fixture now covers 512 original-source
scenarios, including absent/null/returned/throwing avatar callbacks. The connected
HTTP fixture contains 179 checks across login, account provisioning and avatar storage.
With a prepared destination but no simulation connector, login removes presence
and returns the original empty-reason launch failure. /ready remains HTTP 503.

AGENT LAUNCH

AgentLauncher ports LaunchAgentAtGrid, LaunchAgentDirectly and
LaunchAgentIndirectly as a native component. It prefers local simulation over
remote simulation, queries access before creating an agent, passes the same
transfer context between those two operations, and tries online fallback regions
using the account scope. Retries reuse the same circuit and capability seed.
The outbound context packs the original real-valued InboundVersion/OutboundVersion
and integer WearablesCount fields. The native EntityTransferContext now unpacks
these fields using the bundled SDK's numeric conversion behavior.
Direct fallback adds ViaRegionID; HG retries preserve the source's distinct flags
and gatekeeper reuse. Final destination, where and reason follow source behavior,
including connector absence and dependency exceptions. Gatekeeper setup uses the
