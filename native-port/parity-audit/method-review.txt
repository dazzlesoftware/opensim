METHOD-LEVEL PARITY REVIEW - WINDOWS AND LINUX
2026-11-24

This pass validates all 770 declared ll/os overload entry points against native compilers and reviews the original implementations of all 33 rejected APIs. It also reviews two admission lifecycle stubs.
Source-wide member extraction is an index, not a semantic completion audit. It found 27,177 method/property/constructor declarations, including 20,776 in previously unmapped files. Preprocessor/grammar errors are recorded for 16 original and 59 native files; extraction may be incomplete in those files.

RESULTS
Windows: 737 accepted calls, 33 rejected calls. Linux: identical results, no platform disagreement.
All rejected probes report unsupported expression or undefined name. A positive llOwnerSay control passed on both.
Inputs use parameter types from parsed original interface declarations, including every overload; no dummy host or script execution is used.
Compilation acceptance proves entry-point acceptance only. Return values, side effects, permissions, delays, errors, host binding and persistence remain separate obligations.
Linux original lsl_runtime.cpp snapshot SHA-256 matches current Windows source. Linked library and probe hashes are recorded in the platform summaries.

REPRODUCIBILITY
tools/parity_compile_probe.cpp invokes compile_lsl from the actual linked native libraries. tools/review_parity_methods.py extracts interfaces and original members using tree-sitter and runs the Windows probes. probe/run-linux.py runs the same saved scripts in the Linux build image with build/source volumes read-only.
The compiler probes do not execute scripts, contact the test server or change TestBuild accounts/data. Raw call scripts and diagnostics are retained.
